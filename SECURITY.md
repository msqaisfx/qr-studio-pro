# Security Policy

## Supported versions

Until the first stable release, security fixes target the latest code on the default branch.

## Reporting a vulnerability

Please do not disclose a suspected vulnerability in a public issue. Contact the project maintainer privately using the security-reporting channel listed in the GitHub repository once that channel is configured.

Use [GitHub private vulnerability reporting](https://github.com/msqaisfx/qr-studio-pro/security/advisories/new). If that channel is unavailable, do not submit sensitive vulnerability details through a public issue.

Include reproduction steps, affected versions, potential impact, and any suggested mitigation. Do not include real user data or secrets. The project will acknowledge reports and communicate remediation status as maintainer capacity allows.

## Privacy boundary

QR content is designed to remain in the browser. Any change that transmits content, adds analytics, or introduces remote storage must receive explicit security and privacy review.
